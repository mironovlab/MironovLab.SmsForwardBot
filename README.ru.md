# SmsForwardBot

Бот пересылает в личный чат Telegram входящие SMS, отчёты об отправке и доставке, а также системные уведомления gsm-sip-bridge. Исходящие SMS он ставит в очередь через тот же WebUI API, который использует браузер.

`MironovLab.SmsForwardBot` запускает HTTP-контроллер и фоновые службы бота. Логика бота и регистрация зависимостей через `Microsoft.Extensions.DependencyInjection` находятся в каталоге `Bot` этого проекта.

Для исходящих SMS и отчётов об отправке нужна сборка моста с доработками `38ee3ea` и `4e01987` из ветки `feature/ims-sms-send`. Коммит `51c4a9d` добавляет отчёты о доставке и поля `Category` и `Status`, по которым бот распознаёт уведомления. Поддерживаются и вебхуки прежнего формата. Линии VoWiFi и VoLTE поддерживают отправку. Линии GSM могут принимать SMS.

## Настройка

Заполните [appsettings.json](MironovLab.SmsForwardBot/appsettings.json) и перезапустите бота после изменения настроек.

| Параметр | Значение |
| --- | --- |
| `Telegram:BotToken` | Токен бота от [BotFather](https://core.telegram.org/bots/features#botfather) |
| `Telegram:OwnerUserId` | Ваш числовой ID пользователя Telegram. Бот принимает команды только от этого ID в личном чате |
| `Telegram:ApiBaseUrl` | Адрес Telegram Bot API. По умолчанию `https://api.telegram.org/` |
| `Bridge:WebUiUrl` | Адрес WebUI, доступный боту |
| `Bridge:WebUiPassword` | Пароль WebUI |
| `DiscordWebhook:Secret` | Случайная строка из 32–128 букв латиницы, цифр, дефисов и подчёркиваний |
| `DiscordWebhook:LogRawBody` | Записывает исходное JSON-тело вебхука после проверки секрета на уровне `Information`. Установите `false`, чтобы отключить |
| `Urls` | Адрес, на котором бот принимает webhook. По умолчанию HTTP на порту 8090 |
| `Language` | Язык сообщений бота в Telegram. `ru` для русского (по умолчанию), `en` для английского |
| `Logging:LogLevel` | Уровни журналирования Microsoft.Extensions.Logging для приложения и отдельных категорий |
| `StateFile` | Файл состояния. При запуске через `dotnet run --project` относительный путь отсчитывается от каталога проекта |

Бот пишет диагностические логи на английском. Язык ответов и новых уведомлений в Telegram определяется параметром `Language` при запуске. Сохранённые в очереди уведомления отправляются с текстом, сформированным при приёме.

При включённом `DiscordWebhook:LogRawBody` журнал содержит текст SMS и номера телефонов из тела запроса.

При переносе установки в другой каталог укажите абсолютный путь к прежнему `bot-state.json`, чтобы сохранить выбранную линию и очередь уведомлений.

В `config.toml` моста включите WebUI и SMS. Замените `smsforwardbot` на имя или IP хоста с ботом, а `YOUR_WEBHOOK_SECRET` на значение из `DiscordWebhook:Secret`.

```toml
[webui]
enabled = true
password = "env:WEBUI_PASSWORD"

[sms]
enabled = true
discord_webhook_url = "http://smsforwardbot:8090/webhooks/discord/YOUR_WEBHOOK_SECRET"
```

Укажите тот же пароль в настройках бота. Чтобы мост запрашивал у оператора отчёты о доставке новых исходящих SMS, добавьте `request_status_reports = true` в секцию `[sms]` моста с поддержкой этих отчётов. После перезапуска моста запустите бота с установленным .NET SDK 10 или новее и откройте с ним личный чат командой `/start`.

В сборке моста с поддержкой `[alerts]` направьте системные уведомления на тот же вебхук. Выберите нужные категории в секциях `[alerts.<категория>]`. Например, чтобы получать уведомления о потере и восстановлении SIP-регистрации, добавьте в `config.toml` моста:

```toml
[alerts]
discord_webhook_url = "http://smsforwardbot:8090/webhooks/discord/YOUR_WEBHOOK_SECRET"

[alerts.registration_loss]
enabled = true
```

Если у категории задан собственный `discord_webhook_url`, укажите адрес бота и в этой секции. Перезапустите мост после изменения конфигурации.

```powershell
dotnet run --project MironovLab.SmsForwardBot
```

Бот получает команды через long polling. Входящие HTTP-соединения нужны от моста. Для соединений за пределами доверенной сети используйте HTTPS. В файле состояния временно хранятся тексты уведомлений, ожидающих отправки в Telegram. Файл состояния, заполненный `appsettings.json` и URL webhook содержат личные данные или секреты.

## Запуск как служба

Для **systemd** используйте [smsforwardbot.service](deploy/systemd/smsforwardbot.service). Пример запускает исполняемый файл `MironovLab.SmsForwardBot` из однофайловой публикации `FolderProfile` для `linux-x64`. Поместите опубликованные файлы и заполненный `appsettings.json` в `/opt/smsforwardbot`. На сервере нужен ASP.NET Core Runtime 10. Создайте системного пользователя и группу `smsforwardbot` и дайте службе доступ на чтение к файлам приложения и конфигурации и право запуска исполняемого файла.

Если вы опубликовали приложение в виде DLL, укажите `ExecStart=/usr/bin/dotnet /opt/smsforwardbot/MironovLab.SmsForwardBot.dll`. [Варианты публикации .NET](https://learn.microsoft.com/en-us/dotnet/core/deploying/)

При запуске systemd создаст каталог `/var/lib/smsforwardbot` для файла состояния и дождётся уведомления от приложения о готовности. При переносе существующей установки укажите путь к прежнему `bot-state.json` в строке `Environment=StateFile=...` файла службы. [Интеграция .NET с systemd](https://learn.microsoft.com/en-us/dotnet/api/microsoft.extensions.hosting.systemdhostbuilderextensions.addsystemd?view=net-10.0)

Из корня репозитория на Linux выполните команды установки и запуска службы.

```sh
sudo install -m 0644 deploy/systemd/smsforwardbot.service /etc/systemd/system/smsforwardbot.service
sudo systemctl daemon-reload
sudo systemctl enable --now smsforwardbot.service
```

Для **службы Windows** зарегистрируйте опубликованный `MironovLab.SmsForwardBot.exe` в диспетчере служб. Положите заполненный `appsettings.json` рядом с исполняемым файлом. [Развёртывание ASP.NET Core как службы Windows](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/windows-service?view=aspnetcore-10.0)

Для службы укажите абсолютный путь к `StateFile` и предоставьте её учётной записи право записи в каталог этого файла.

## Команды

В личном чате отправьте `/start` или `/help`, чтобы открыть клавиатуру бота. Запускайте действия кнопками или командами без параметров. Бот запрашивает данные по шагам. При ошибке он повторяет текущий шаг. Новая команда отменяет незавершённый ввод.

| Команда | Действие |
| --- | --- |
| `/send` | Запрашивает номер получателя, затем текст SMS и отправляет его с текущей линии |
| `/reply` | Показывает номер отправителя последнего входящего SMS и запрашивает текст ответа |
| `/lines` | Показывает обнаруженные мостом линии, режим выбора и кнопки доступных для выбора линий |
| `/line` | Предлагает выбрать линию VoWiFi или VoLTE кнопкой либо ввести её ID |
| `/auto` | Возвращает автоматический выбор по последнему входящему SMS |
| `/cancel` | Отменяет незавершённое действие |

В автоматическом режиме бот сверяется с журналом SMS моста и полученными webhook. Пока входящих SMS нет, он использует единственную линию с поддержкой отправки или предлагает выбрать её вручную. Если линия последнего SMS больше не поддерживает отправку, бот попросит указать другую. Ручной выбор и очередь уведомлений сохраняются при перезапуске. После перезапуска начните незавершённое действие заново. Запускайте один экземпляр бота на токен и файл состояния.

Для `/send` и `/reply` бот удаляет из номера пробелы, тире и круглые скобки. После этого в номере должно быть от 3 до 20 цифр. В начале допустим один `+`.

`/reply` фиксирует номер отправителя и линию последнего входящего SMS, когда запрашивает текст ответа. Для ответа нужна линия с поддержкой отправки. Ручной выбор через `/line` применяется к `/send`.

Сначала бот показывает номер записи в SMS Outbox. Затем он пересылает отчёт об отправке, когда SMS-центр принял все части или мост завершил попытки отправки. Если операторские отчёты включены, бот также пересылает итоговый статус доставки. Сообщение может быть доставлено полностью, доставлено частично, не доставлено или получить неизвестный статус, если отчёт оператора не пришёл вовремя. Номер SMS Outbox в обоих уведомлениях связывает их с командой `/send` или `/reply`.
